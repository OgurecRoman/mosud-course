# Практическая работа №4

Вариант 10: «Паспорт заказа» (`orders + customers + агрегированные items + payments + reviews + sellers`). Учтены заказы со статусом `delivered`.
Запуск: `psql -U postgres -d olist -q -o result.txt -f lab04.sql`

## Кратности связей

| Связь | Кратность | Что делаем |
|-------|-----------|------------|
| orders → customers | N:1 | обычный `JOIN` |
| orders → order_items | 1:N | агрегируем до одной строки на заказ |
| order_items → sellers | N:1 | `JOIN` внутри агрегата items |
| orders → order_payments | 1:N | агрегируем до одной строки на заказ |
| orders → order_reviews | 1:N | агрегируем до одной строки на заказ |

## Результаты

| Проверка | Значение |
|----------|---------:|
| Доставленных заказов | 96 478 |
| Строк в «паспорте» (одна на заказ) | 96 478 |
| Заказов без платежей / без отзывов | 1 / 28 968 |
| Заказов без отзыва (все статусы): `LEFT JOIN IS NULL` = `NOT EXISTS` | 29 979 |

Ошибочный JOIN `items × payments` против эталона:

| | Строк | `SUM(price)` |
|---|------:|-------------:|
| Ошибочный (прямой JOIN по `order_id`) | 115 035 | 13 813 828.71 |
| Эталон (только `order_items`) | 110 197 | 13 221 498.11 |
| Исправленный (предагрегация, inner join) | 96 477 | 13 221 363.14 |

## Реляционная алгебра

```
π[...]( σ[order_status = 'delivered'](
    ((( orders ⋈ customers ) ⟕ γ( order_items ⋈ sellers )) ⟕ γ( order_payments )) ⟕ γ( order_reviews ) ))
```

⋈ — эквисоединение, ⟕ — левое внешнее соединение, γ — группировка с агрегатами.

## Выводы

- Каждый агрегат даёт одну строку на заказ, поэтому «паспорт» не размножает строки: 96 478 строк на 96 478 заказов.
- `LEFT JOIN` сохраняет заказы без отзывов и платежей (в их столбцах `NULL`).
- Прямой JOIN `items × payments` размножает строки: заказ с 3 позициями и 21 платежом даёт 63 строки, и цена каждой позиции считается 21 раз. Сумма завышается на ~592 тыс. (4,5%).
- Исправленная сумма (13 221 363.14) на 134.97 меньше эталона: у одного доставленного заказа нет платежей, и inner join его отбросил.
- Таблица `order_reviews` в моей БД содержит 69 610 строк, а в методичке ориентир 99 224. Причина не выяснена, возможно, CSV загрузился не полностью.

## Контрольные вопросы

1. **Почему соединение `order_items` и `order_payments` по одному `order_id` может завысить `SUM`?** Оба отношения связаны с заказом как 1:N, поэтому для заказа получается произведение числа позиций на число платежей. Каждая цена повторяется столько раз, сколько у заказа платежей.
2. **В чём отличие `LEFT JOIN ... WHERE right.id IS NULL` от `NOT EXISTS`?** Результат одинаков, пока проверяемый столбец `NOT NULL`. `LEFT JOIN` строит соединённые строки и отфильтровывает совпавшие, а `NOT EXISTS` только проверяет наличие совпадения и ничего не размножает. Если проверять столбец, допускающий `NULL`, первый вариант даст ложные срабатывания.
3. **Как представить эквисоединение через декартово произведение и выборку?** `R ⋈[a=b] S = σ[R.a = S.b](R × S)`. Берём все пары кортежей и оставляем те, где значения совпадают.
