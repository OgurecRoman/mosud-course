# Практическая работа №2

Вариант 10: штат X = MA, штат Y = PI. Учтены только заказы со статусом `delivered`.
Запуск: `psql -U postgres -d olist -q -o result.txt -f lab02.sql`

| Множество | Строк (`count(*)`) | Уникальных товаров (`count(DISTINCT)`) |
|-----------|-------------------:|---------------------------------------:|
| A (MA)    | 800                | 657                                    |
| B (PI)    | 523                | 446                                    |
| A ∪ B (`UNION`)     | -        | 1046                                   |
| A ∪ B (`UNION ALL`) | 1323     | -                                      |
| A ∩ B (`INTERSECT`) | —        | 57                                     |
| A − B (`EXCEPT`)   | —         | 600                                    |
| B − A (`EXCEPT`)   | —         | 389                                    |

Проверки: |A ∪ B| = 657 + 446 − 57 = 1046; |A − B| + |A ∩ B| = 600 + 57 = 657 = |A|.

## Контрольные вопросы

1. **Почему `UNION` обычно дороже `UNION ALL`?** `UNION ALL` просто склеивает результаты. `UNION` ещё и удаляет дубликаты, для этого нужна сортировка или хеширование всех строк.
2. **Почему без `ORDER BY` нельзя делать выводы о порядке?** Отношение является множеством кортежей, и порядка у него нет. Порядок строк в выводе зависит от плана выполнения и физического хранения, и без `ORDER BY` СУБД его не гарантирует.
3. **Чем множество отличается от мультимножества?** В множестве каждый элемент встречается не более одного раза. В мультимножестве элемент может повторяться, и учитывается кратность (сколько раз он встречается). Реляционное отношение — множество, а результат SQL-запроса по умолчанию — мультимножество.
