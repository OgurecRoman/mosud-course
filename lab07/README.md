# Практическая работа №7

NULL, трёхзначная логика и качество данных на таблицах `orders`, `products`, `order_reviews`, `order_items`.
Запуск: `psql -U postgres -d olist -q -o result.txt -f lab07.sql`

## Контрольные вопросы

1. **Почему NULL = NULL не даёт TRUE?** NULL означает неизвестное значение. Два неизвестных значения могут быть как равны, так и различны, поэтому результат сравнения `UNKNOWN`, а `WHERE` оставляет только строки с `TRUE`. Для проверки пропуска используется `IS NULL`, для сравнения с учётом NULL — `IS NOT DISTINCT FROM`.
2. **Как предикат в WHERE влияет на строки, созданные внешним соединением?** Для строк без пары в `LEFT JOIN` столбцы правой таблицы равны NULL, и условие вроде `r.review_score >= 4` для них `UNKNOWN`, поэтому `WHERE` их отбрасывает. `LEFT JOIN` фактически превращается в `INNER JOIN` (53608 заказов вместо 99441). Условие в `ON` только определяет, какие строки правой таблицы подходят в пару, а левые строки сохраняются.
3. **Почему NOT EXISTS устойчивее NOT IN при возможных NULL?** `x NOT IN (..., NULL)` раскрывается в цепочку `x <> ... AND x <> NULL`, которая не бывает `TRUE`, поэтому запрос возвращает 0 строк. `NOT EXISTS` проверяет только наличие подходящей строки по условию соединения, NULL в подзапросе его не ломает.
